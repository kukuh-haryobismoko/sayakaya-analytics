03
NEW SINCE JULY · 01

Every user now has their own login — and a paper trail

In July, the dashboard was one shared password. It's now a per-user system with self-service invites, password resets, roles, logging, and watermarking on every export.

Invite-by-email account creation

No more shared password. An admin invites a teammate with just their email — the system sends an activation link, and the new user sets their own password on first login. Login now works with either username or email.

Self-service password reset

Forgot a password? Users request a reset link themselves. The reply never reveals whether an account exists, the link expires in 30 minutes, and resetting a password immediately signs that user out everywhere else.

Full audit log

Every login and every export is logged and searchable by user and date, in its own Activity log tab.

Export watermarking

Every CSV, Excel, and PDF a user downloads is stamped with who pulled it and when — no anonymous exports.

Also: sensitive fields (passwords, KYC) stay redacted at the query layer for every user, sessions now expire after 8 hours (down from 7 days), and setting up an automated email schedule requires a 6-digit OTP confirmed by email before it goes live.
04
NEW SINCE JULY · 01b

Role-based access control, live and verified in production

Access starts at zero. An admin grants each person exactly the sections they need, tab by tab, across all 28 sections — nothing is on by default.

Section-level, not all-or-nothing

Every one of the 28 sections — Dashboards, Investor, Operations & Finance, Tools/Docs/Admin — is its own checkbox in the admin panel, grantable individually in any combination.

Two tiers

Standard users see only the sections checked for them. Superusers always see everything, including User management and the Activity log.

Enforced twice, not just cosmetic

The same permission set hides the tab in the sidebar and blocks the underlying API — a direct request to a restricted section is rejected server-side, not just hidden in the UI.

Verified this cycle

Confirmed end-to-end in production: inviting a user, scoping them to a handful of sections, and both the sidebar and the API respecting exactly that scope.

English or Bahasa Indonesia — and a second, independent backend

🇬🇧 / 🇮🇩 Bilingual dashboard

GOVERNANCE

More guardrails, not fewer

Cost caps

Every query — including AI-generated ones — carries a hard byte-billed cost cap, estimated before it runs.

No SQL injection

All user input — dates, filters, search — is a named parameter. Never string-concatenated into a query.

Sensitive data blocked

Passwords and KYC documents are blocked at the query layer — never selectable, even in free-text SQL.

Read-only by design

Free-text SQL is read-only only. ML models are trained separately and only ever called at runtime.

New this cycle:  per-user roles  ·  export watermarking  ·  full login/export audit log  ·  sessions shortened to 8 hours
11
WHY IT MATTERS

What this project actually buys the business

Faster, more confident decisions

Asking a question about the business no longer waits on an engineer to write SQL — the answer comes back in seconds, from live data. Decisions move at the speed of the question, not the speed of a request queue.

Lower operational risk

Who saw what, and who exported what, is now recorded and traceable — not a single shared password with no trail. If something ever needs to be traced back, the record already exists.

Investor trust, protected at scale

Reports, statements, and eligibility processes now run themselves, consistently — but every automated action is still logged and reviewable one by one. Moving faster hasn't come at the cost of accountability.

Resilience — no single point of failure

Two independent hosting backends and two independent schedulers mean investor communication and reporting don't depend on any one vendor staying up.
